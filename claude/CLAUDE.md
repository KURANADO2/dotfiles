# CLAUDE.md（用户级，所有项目通用）

## 交流语言约定（最高优先级）

- 与用户的一切交流使用中文：设计方案、技术陈述、提问、进度汇报；提供方案选项时，选项文字与描述也必须中文
- 中文文本一律使用全角标点：，；：？！（）「」/“”、。禁止在中文语句中使用半角 `,` `;` `:` `?` `!` `()`
  - 例外：代码块、行内代码、命令行、SQL、文件路径、日志摘录、URL 及程序标识符内部保持半角；中文句子中嵌入的英文缩写（如 RAG、GRANT）不改变该句的全角属性
  - 适用范围：对话回复、邮件/IM 草稿、方案选项，以及为用户生成的文档文件中的一切中文叙述
- 段末标点与编号（「段末」指独立段落、列表项、表格单元格结尾处）：
  - 段末不落句号「。」、不落分号「；」，段中间正常使用；段末问号「？」保留
  - 列举条目与标题编号一律用阿拉伯数字（1. 2. 3.、「## 1. xxx」），禁止「甲、乙、丙」「①②③」「（一）（二）」「一、二、三」

## 技术解释通俗化约定

目标：第一次回答就通俗，不等用户追问「太抽象看不懂」。通俗化不是删减技术内容，而是保留精度、重排呈现层次。写技术解释前逐条对照：

1. 先还原现场，再讲机制：用用户问题里的真实例子开场，把系统内部发生的事讲成具体场景（谁、拿到什么、做了什么、返回了什么），禁止内部名词开路
2. 内部标识符先翻译再使用：类名/字段名/表名首次出现先用一句话说明现实含义（如「SynthesisBatch（一批 = 一次 LLM 调用）」）；有日常说法优先用日常说法（「证据卡」优于「referenceChunkIdsJson 字段」）；代码块内部不受此限
3. 讲权衡取舍必配生活化类比：类比要能映射到关键取舍点，不是装饰性比喻
4. 代价与后果写成可感知的画面 + 具体数字：不说「指标被系统性稀释」，说「就算真正相关的 3 个全找到，得分也只有 3/9」；数字用具体值不用抽象比例
5. 用用户会自然问出的问题推进叙事：小标题按「那系统为什么不自己猜？」「猜错的后果是什么？」走，不用「机制原因/同构先例/代价分析」论文式框架
6. 实物证据优于抽象描述：能贴真实 JSON 片段、真实编号、真实数量就贴

发送前自检：假设读者是「懂业务但不熟这份代码的同事」，凡出现「没解释就用的内部名词」「没有画面感的机制描述」「没有类比的权衡取舍」「没有具体数字的代价陈述」，就地重写该段。
适用范围：根因分析、取舍解释、架构说明、方案对比、缺陷影响等一切「向用户解释技术」的场合；代码、commit message、面向 agent 的交接文档不受此约束；用户要求「直接给结论/简洁点」时按用户要求。

## Java 代码检索工具分工（语言服务器 / 知识图谱 / grep）

### 首选语言服务器（Eclipse JDT.LS）——精确、类型级、编译期问题

引用查找（findReferences，「删了会不会编译报错」）、跳定义/找实现/重载消歧、调用层级、看签名泛型、编译诊断。理由：基于真实类型解析，认重载/泛型/继承/测试源根，实时无索引滞后。

### 首选知识图谱（codegraph 类）——语义、流程、批量上下文问题

自然语言问架构与链路（codegraph_explore，一次返回多符号源码全文）、模糊找位置（codegraph_search）、单符号取全文与重载消歧（codegraph_node）。

### 硬性规则

1. 引用计数/影响面/删除安全性一律以语言服务器 findReferences 为准；codegraph_callers/impact 会漏调用点，不得单独作结论，只能当补充线索
2. 计数类结论必须 grep 全仓交叉验证（含 src/test）；三方对不上时以 grep 与语言服务器的并集为准，并向用户说明差异
3. 语言服务器降级时必须显式告知用户，禁止静默退回图谱并宣称结论可靠。降级特征：引用查找只返回声明自身、诊断出现 non-project file only syntax errors；此时语法级操作（documentSymbol）仍可用，语义级（引用/跳转/层级）全部不可信
4. 首次在某个 Java 工程使用前确认实例健康：`pgrep -fl org.eclipse.jdt.ls.core.id1`，检查各实例 -data 工作区目录是否被多实例共用（共用即冲突，语义结果不可信）

### 降级的成因、探测与修复

- 成因：jdtls 启动器按**工作目录 basename** 的 sha1 派生缓存目录（`~/Library/Caches/jdtls/jdtls-<哈希>`）——目录同名即共用缓存，撞车后 Maven 工程配置被打断，Java 特性被摘、源文件降级成散文件
- 健康探针（用前先查）：`grep -c "has no .classpath" ~/Library/Caches/jdtls/jdtls-*/.metadata/.log`，>0 即已损坏；若日志无 Could not resolve 且 .classpath 都在，即与依赖/网络无关，纯属并发损坏
- 修复：杀全部 jdt.ls 实例 → 删除损坏缓存目录（仓库 .classpath/.project 保留可复用）→ 重开会话重新导入 → findReferences 复验（返回多于声明自身即恢复）。损坏是持久的，不会自愈
- 预防：一个工作目录同一时刻只允许一个会话使用语言服务器；并行任务一律「一会话一工作树」且目录名互不相同（EnterWorktree 建的名字天然唯一），或只在主会话启用 jdt.ls、其余走图谱+grep
- 遗留实例：插件目录 `~/.claude/plugins/cache/*/jdtls-lsp/*/.in_use/` 的标记存在但进程已不在 = 异常退出残留，可能仍占着缓存目录

### Lombok 接入（已修复，存档）

- `/opt/homebrew/bin/jdtls` 已改为指向 `~/.local/share/jdtls-lombok/jdtls` 的转接脚本，自动挑 `~/.m2` 里最新版 lombok 追加 `-javaagent`；原目标记在同目录 ORIGINAL_SYMLINK_TARGET.txt，原脚本备份为 jdtls.orig
- `brew upgrade jdtls` 会还原该链接，届时重跑：`ln -sf "$HOME/.local/share/jdtls-lombok/jdtls" /opt/homebrew/bin/jdtls`
- 排查口诀：诊断成片「某实体的 getXxx/setXxx 未定义」或「log 无法解析」，先 `ps -o command= -p <jdt.ls 进程号> | grep javaagent`，为空即 Lombok 掉了，不要当代码问题；Lombok 失效还会导致引用查找漏项

## 工作树隔离约定（并行会话的默认行为）

用户会并行开多个会话处理同一仓库。处理代码改动的任务默认在独立 git 工作树里进行：

- 开始任何会写文件的任务前先调 EnterWorktree；纯查询、问答、只读分析不触发
- worktree.baseRef 已设为 head（~/.claude/settings.json），不要改回 fresh——fresh 从 origin 切分支，会丢掉本地未推送提交作为基线，合并必冲突
- 收尾用 ExitWorktree：无需保留选 remove，需保留选 keep；有未提交改动时 remove 会被拦，先与用户确认
- 提交只挑本任务的文件；工作区里非本任务的改动属于其他会话，禁止删除、回滚、覆盖

## 开发完成一律自动合入 main

1. 工作树开发完成、提交后，一律自动把分支合入 main，不询问「是否需要合并」
2. 合并前先在主仓库工作目录 `git pull origin main`，让本地先跟上远程，冲突在这一步暴露并由 AI 解决
3. 冲突由 AI 当场解决，禁止甩给用户或建议用户新开会话；解决后按项目约定验证（Java 仓库 `mvn clean install` 带测试，`-DskipTests` 会掩盖测试侧断裂），无断裂才算完成
4. 永远不自动 push：合并后停在本地，除非用户在本次对话中明确允许；某次允许只对当次生效

操作顺序（主仓库工作目录）：`git pull origin main` → `git merge <分支>` → 解决冲突并验证 → ExitWorktree。若主目录存在其他会话的未提交改动且阻碍合并：禁止删除/回滚/覆盖，向用户说明等待决定。
